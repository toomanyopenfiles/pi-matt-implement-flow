pi-matt-implement-flow · 课程 0002（v2 重排版）

一张票的完整旅程：派发 → 审查 → 修复 → 合并

使命：维护并演进这个插件 · 预计 15 分钟 · 前置：0001 循环骨架

开课前 1 分钟 本课只讲一条主线：一张票从认领到关闭，每一步是谁在干什么、拿什么进、出什么。所有 git 命令在 git 最小词典里都有人话解释（git 不熟就先花 5 分钟扫它的 A、B 两节，回来读正文不卡）。机制原理和设计史压缩在 §4 与折叠盒里，主线不经过它们。

§1八步旅程（总表）

三个执行者：编排者（你自己，在主检出干所有 git 活）、pi-matt-implement-flow.coder（实现者，只待在自己的 worktree）、pi-matt-implement-flow.reviewer（只读审查者）。一张票的旅程：

步执行者干什么（目标）输入 → 输出git 命令
①编排者 认领前沿票，写 brief（全是指针：票路径、spec 路径、测试命令），派 coder 票文件 + spec → coderRunId（记台账） （无——这是 pi 派发）
②coder 在自己专属的 worktree 里按票实现，测试先行（红→绿），把一切提交 brief → commit 落在自己的 pi 分支 + 结构化报告（headSha、commits、测试结果、seams） add -A、commit
③编排者 锚定：不信报告里的 SHA，问 git 要真值，把产出固定成主仓库里的真票分支；顺手打包审查输入 coder 报告（只是线索）→ 真票分支 ticket-01 + review bundle（三点 diff + 提交列表，一个文件） rev-parse、branch、diff ...、log
④reviewer 两轴审查（仓库标准轴 + spec 对照轴），只读，不信任 coder 的报告 bundle 路径 + 票 + spec + 测试门证据 → verdict（approved / changes_requested）+ findings （无——它没有 bash）
⑤ 分叉点：approved → 直接跳 ⑧；changes_requested → 进修复回路 ⑥⑦（最多 2 轮，超了记 escalated，继续别的票）
⑥编排者 → 同一个 coder 编排者把 findings 写成文件，用新 key resume 唤醒原 coder（worktree、上下文原样保留）→ coder 读 findings 原地修，新 commit 落在同一分支 findings 文件 → 新的 commit（仍在 pi 分支上） （coder 侧：commit）
⑦编排者 代跑测试门（平台修复轮不收 gate 参数）→ 把票分支移到新 SHA → 重建 bundle git 真值 → 移动后的票分支 + 新 bundle（-r2） rev-parse、branch -f、cd … && npm test
⑧编排者 真合并（强制产生合并提交）→ 跑全量集成测试 → 关票（附 merge SHA）→ 清理 worktree 与票分支 → 重算前沿 过审的票分支 → merge commit + 关闭的票 + 干净的现场 merge --no-ff、branch -D、worktree remove
贯穿全程的判定纪律 ③⑦ 两步都先 git rev-parse 取真 SHA 再动手——因为实测里 run 状态会说谎（failed 但 commit 已落地）、coder 会编造 SHA。报告和状态只是线索，git 真值才是证据。

§3git 命令与流程的对应（四类活）

把 §1 表格最后一列单独拎出来，git 在整个流程里只干四类活：

  1. 问真相：rev-parse——任何时候想知道「分支实际指向哪个 commit」就用它（把名字翻译成 40 位真 SHA）。
  2. 立标签：branch（创建）与 branch -f（强制移动）——票分支的生与挪。记住：分支只是一张写着 SHA 的标签纸。
  3. 做合并：merge --no-ff——票进主线的唯一通道。
  4. 看与清：diff ... + log（打包给 reviewer）、worktree remove + branch -D（收尾）。

每条命令的完整人话解释、porcelain 输出怎么读，都在 git 最小词典——练习卡壳先查它，不用回正文翻。

§4为什么修复要送回同一个 coder？（30 秒版）

  1. 上下文是钱：原 coder 已经读过票、spec、相关代码。换新 coder 要从零重建理解，成本翻倍。
  2. 不带新偏见：新 coder 等于换一个人重做，容易推倒已审过的决策；原 coder 只需针对 findings 精准修。
  3. 物理上可行：pi 在 child 可 resume 时故意保留它的 worktree 和分支——resume 回到原地继续。coder 的 worktree 不是临时工棚，是它的固定工位（②里"专属"的真正含义）。
