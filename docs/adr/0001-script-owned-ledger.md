# ADR-0001: 脚本独占台账写权，LLM 只记账

- **Status:** accepted
- **Date:** 2026-09-18
- **Deciders:** 本包维护者（经 grill 会话定稿）
- **Context tags:** orchestrator-memory, ledger, enforcement

## Context

编排器在 compaction 之间唯一的跨会话记忆曾是一个手工维护的台账文件（markdown 表格 + 散文
事件日志），其更新义务全部写在 SKILL.md 的提示词里。第二次实战（st-babel-eval /
parse-bilingual-alignment）暴露出这一记忆层**结构性地**不可信，出过三类 P0 事故：

1. **表格尾态失真**：最后一次合并之后无人对账，表格仍显示工单 claimed/open、PR 仍标 draft，
   而 git/票文件/PR 真相是全部 done、PR 已转正式——compaction 后的新会话按 SKILL 指引
   第一件事读台账，读到的却是错误状态。
2. **散文日志覆写与乱序**：append-only 纪律靠 LLM 用 edit 工具维持，一次覆写事故靠手工
   "更正条目"抢救；无时间戳，时序倒挂无法自动检测。
3. **前置检查结论未经验证**：`.scratch/` 是否被 gitignore 的判断写错进了台账头部，
   base 字段混用两种语义。

根因不是模型偶发失误差，而是结构性的：表格更新义务（每次从真相再生）与事件日志纪律
（append-only）都是提示词规则，靠模型注意力概率性执行；两条义务的成本差稳定产出
"诚实的日志 + 失真的表格"。同时约 8 条记账纪律条款占用编排器注意力，挤压编排本职
（何时派发、何时评审、何时合并）的上下文。

## Decision

**LLM 永不手写台账。** 三层模型，写权机械分离：

- **真相层（脚本只读）**：git 历史、分支、worktree 列表、票文件 `Status:` 行、
  gh PR 状态（best-effort，不可用时标未知，不编造）。
- **事件流（LLM 唯一状态写面）**：append-only JSONL，一行一个结构化事件；唯一写入路径是
  脚本的记账命令（`add`）——脚本盖权威时间戳与单调序号、做三档校验（拒绝 / 警告 / 矛盾拒绝）、
  append 成功后自动再生台账。SKILL 禁止任何直接 shell 追加或 edit 工具触碰事件流与台账。
- **台账（派生层，脚本独占写权）**：由事件流 + 真相层全量再生的人类可读 markdown，
  临时文件 + 原子替换写入，随时可确定性重建。

纪律从约 8 条散文收敛为 3 条命令纪律：状态转换时记账（`add`）、派发与合并前对账（`check`）、
compaction 后再生（`build`）读输出。

## Alternatives considered

**纯纪律 markdown 台账（否决）**——维持现状：LLM 继续手写台账，靠提示词条款约束更新义务。
两次实战各出一次 P0 事故证明该方案的概率性失效不可接受；且每轮都要花编排注意力在
"我该怎么把表格改对"上，而机械可执行的部分本可以交给脚本。不选"更强的提示词"
（更醒目的措辞、更多检查清单）：那是在用一个概率机制修补同一个概率机制的已知失效模式。

**LLM 直写 JSONL + 脚本只读**（否决）——事件流仍由 LLM 直接写：时间戳、序号、HEAD 锚点
都要靠 LLM 自觉生成，覆写与乱序风险原样保留，只是把表格问题换成了 JSON 问题。
写面收敛到记账命令才使校验与自动再生有单一的挂载点。

**脚本直写票文件 / 计算 frontier**（否决，v1 范围外）——票文件 Status 行与编排决策
（frontier、下一步建议）留给 LLM：脚本只做账实一致，不做编排决策。本 ADR 只裁定
"台账与事件流的写权归脚本"，不扩大脚本职权。

## 论证：为什么满足记 ADR 的三条件

1. **难逆转**：运行时协议（compaction 恢复 = 跑脚本读输出、派发/合并前的对账门、
   fix 预算的写点执法）一旦建立，运行流程就依赖"台账永远可信"这一前提；
   退回手写台账意味着重立全部纪律条款并重训自己的使用习惯，更换成本高。
2. **无上下文会困惑**：未来读者会问——LLM 明明能写文件，为什么 SKILL 禁止它碰台账？
   不知道两次实战的表格失真与日志覆写事故，这条禁令看起来像多余的仪式。
3. **真实取舍**：本决策不是免费的正确性——脚本成为承重件（台账语义从散文搬进代码），
   必须有测试守护；LLM 失去"随手修表格"的逃生通道，与校验器分歧时只能记异常事件
   （anomaly）并停下上报。接受这个代价，换取记忆层从概率性正确变为机械正确。

## Consequences

- 编排器写面收敛：状态转换一律记账，"更新台账"作为独立步骤消失（随记账自动再生）。
- 脚本成为承重件：事件分类学固化为枚举 schema，最小状态机在写点执法（违规事件不可能进账），
  正确性由 fixture 临时仓上的 CLI 黑盒测试守护，而非模型注意力。
- 台账永不含虚构事实：gh 不可用标未知、事件流丢失走可见降级，不静默编造。
- 散文与事实分家：过程叙事/教训/用户拍板迁往编排笔记，"事件日志"一词退役。
- 历史运行的已归档台账不迁移；旧散文日志保留原样，仅作考古材料。
