编排循环一页纸

从课程 0001 压缩而来 · 权威出处：SKILL.md + docs/design/

A轮次骨架（每轮 8 步）

  1. 前置检查 — git status --porcelain 为空（未跟踪也算脏；脏则整轮派发失败）；票图每票有 Blocked by 且前沿非空。
  2. Round 0（一次） — 读 spec+票入台账；建 feat/<slug>；全量测试记基线；有远端开 draft PR。
  3. 认领·派发 — 数 running coder，低于 N 补满前沿票；一次顶层 workflow（async:true）+ runs.all，每票：worktree + gate + outputSchema。
  4. 锚定 — git rev-parse 那条 pi 分支取真值（不信报的 SHA）→ git branch ticket-N <SHA>；写三点 diff bundle 到 .pi/matt-implement/…/reviews/。
  5. 两轴 review — reviewer 只读 worktree（baseRef: refs/heads/ticket-N，无 bash），fanout 两个 fork 轴 child，聚合后给 approved | changes_requested。
  6. 修复（≤2 轮） — findings 写文件；runs.run(newKey, { resume: coderRunId })；gate 被拒 → 父代理自己在 coder worktree 跑全量测试；判定只看新 HEAD SHA。超 2 轮 → escalated，票保持 claimed。
  7. 合并·关票（串行） — git merge --no-ff ticket-N（冲突走 resolving-merge-conflicts）；合并后跑全量测试（红了→一个无隔离 fixer）；按 tracker 关票带 merge SHA；回收 worktree + 删票分支。
  8. 重算前沿 — 有票回 1；票尽 → 最终门（整支两轴 review → 修 → push → PR ready → 清理一切）。

C硬规则（违反即流程 bug）

  • 派发用全名：pi-matt-implement-flow.coder/.reviewer/.final-reviewer——裸名撞内置与用户别名。
  • 只传指针（路径 / SHA / 分支名），不搬内容。
  • 判定只看 git 真值；run status 与散文报告只是线索。
  • 裁决词表：approved / changes_requested / ready / ready_with_fixes / not_ready——绝不用字符串 blocked（lane 语义保留字）。
  • 合并串行；无隔离 fixer 一次一个；一个 worktree 一个写者。
  • 不发明的并行：依赖工作串行，只有前沿票并发。
  • 两轮修复后升级——卡票不阻塞前沿。
  • 平台基础设施故障 → 停下报告，绝不自己顶上、不静默换模式。
  • 压缩后：重读 SKILL.md → 台账 → git worktree list + git branch 对账，再派发。
